# Observability and Incident Response

## Signals

Track request volume, latency, error rates, retrieval confidence, fallback frequency, token usage, and citation coverage. These signals help distinguish application failures from knowledge-base gaps.

## Incident response

When an incident occurs, identify the affected service and time window, preserve relevant logs, mitigate user impact, and communicate status. After recovery, document the root cause and follow-up actions.

## RAG-specific monitoring

Sudden increases in web fallback, empty citations, or low retrieval confidence may indicate stale documents, indexing failures, or a model change.
