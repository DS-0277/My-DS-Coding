# Assignment - Multi-Subnet Network Topology & Load Balancer Implementation - AD371 (Week 5)

*1. Objective:* In modern cloud and enterprise systems, applications are never deployed to flat, unprotected networks. Application architects design isolated network segments (public ingress vs. private application tiers) and use load balancers to distribute traffic, terminate TLS, and prevent single-point-of-failure bottlenecks. When developers use AI to generate infrastructure configurations (e.g., Docker Compose networks, Terraform, Nginx configs, or cloud VPC templates), LLMs often take dangerous shortcuts—such as binding private backend containers directly to host ports, hallucinating non-existent upstream directives, or creating flat networks where every service can touch the public internet. In this assignment, you will: (1) Use an AI tool to generate an initial draft of a multi-subnet network topology with a functional load balancer (e.g., Nginx, HAProxy, Envoy, or cloud ALB/Traefik) distributing traffic across multiple backend web application instances; (2) Audit and verify the AI-generated network definitions to enforce subnet isolation (public vs. private tiers) and verify load distribution algorithms (Round-Robin, Least Connections); (3) Execute a structured Web Project QA test suite to verify traffic balancing, zero-downtime failover, and network segmentation; (4) Deploy and submit your project with a GitHub repository, AI prompt log, live URL (if applicable), and a video walkthrough demonstrating functionality, failover, and networking tests.
