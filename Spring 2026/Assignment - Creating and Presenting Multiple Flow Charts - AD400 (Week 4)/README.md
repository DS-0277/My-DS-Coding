**2. Basic Flow Chart - Customer Shopping Flow:** With respect to this chart, it outlines the overall flow of e-commerce transactions from the beginning to the end. To start with, users will see the homepage where they can browse for any preferred products of choice to check for the product detail. If users are satisfied with the product, they may add such item to the cart and search for other products if needed. When finishing the search, users can view their cart and proceed to checkout and payment.

**3. System Flow Chart - E-Commerce App Architecture:** This flow chart provides the mapping of system flow or archtecture explaning how frontend connects with backend and database and how external services are connected. To start with, when users open and use the app on the browser, they interact with frontend was displayed on screen. Under the hood, there are three pieces: (1) UI Components; (2) React Query or TanStack Query (fetching data); (3) Zustand (state management). Turning to the backend and database, we may use Supabase where it handles 4 main things: (1) Storage; (2) PostgreSQL Database; (3) Auth Service; (4) Edge Functions (server logic). The last section of the architecture is the interaction with external services like Stripe (handles payment processing) and Email (sends order confirmation receipts). 

**4. Workflow Diagram - Feature Development Lifecycle:** This diagram describe feature development lifecycle when we want to add any new features. First, we can think of any feature and create Figma wireframe along with GitHub issue before buidling UI components. Next, we connect with the database and do unit testing with Vitest to see if any errors exist. If the feature works perfectly, we can open a pull request for code review before merging into main branch. Lastly, we use the finished feature to deploy for production. 

**5. Data Flow Chart - E-Commerce Data Movement:** This flow chart describes how data flows from location to another as we could distinguish the flow into 3 groups. The first group is about authentication starting when users log in with credentials as the data flows through Supabase Auth Users Table and then to Zustand Store before returning the user state to user's browser. The second group is concerned with search query where users browse for products so the data will flow through Supabase Database Products Table and Supbase Storage Product Images before rendering product information and images to the users. The third group is about the payment and order confirmation as data flows from order form to the Supabase Database Orders Table and lastly returning to users.

**6. Decision Flow Chart - Checkout Decision Logic:** This flow chart outlines the logic and decision for user journey in particular on checkout stage and this is divided into 4 main decision questions or gates to be completed step-by-step. The first question is whether users are logged in since identity is crucial at the outset. The second question is whether the cart is empty as we do not want users to checkout with empty items since it affects their experience and waste payment API calls. Next, the third question addresses whether payment is valid to be processed otherwise an error will exist. The last gate will check whether the payment is successful so that a confirmation email will be sent to users. 

**7. Swimlane Flow Chart - Checkout Responsibilities:** This flow chart visualizes responsibilities between different individuals and in this case into 4 various lanes. The first lane shall be the 'Customer' where such user is dealing with various activties such as browsing products, adding items to cart, reviewing order, filling payment information and receiving confirmation email. The second lane is 'React Frontend' where frontend is responsible for displaying component, validating form inputs and showing order summary. The third lane is 'Supabase Backend' as the Supabase is responsible for authenticating user verification, fetching data from the database and sending confirmation email to users. The fourth lane is 'Stripe' which is in charge of payment processing and returning payment resutl to the frontend and backend.
